# Docs index

One topic per file. Keep every page current with reality — a doc that
lies is worse than no doc. Add new pages here when created.

| Doc | What it holds |
|---|---|
| [ARCHITECTURE.md](ARCHITECTURE.md) | How the project is built: modules, data flow, decisions |
| [HOW_TO_RUN.md](HOW_TO_RUN.md) | Prereqs, setup, run, verify |
| [PLAN_NOTES.md](PLAN_NOTES.md) | Phase plan, version pins, deferred ideas |
| [HANDOFF.md](HANDOFF.md) | Where we left off, gotchas, next steps |

House patterns used across our repos (add the ones this project needs):

- `CHANGES.md` — one line per modified file vs an upstream pin (forks
  like DST-Comet); lives in `Docs/`.
- `DESIGN.md` — visual/UX decisions when the project has a UI.
- `QA-*.md` — per-feature QA session logs when verification is manual.
